# Astrobirth 시청자 가이드

헌영의 아이작 대결을 처음 보는 시청자에게 변경 기능과 관전 포인트를 설명하는 한국어 정적 사이트입니다. 모드 실행 코드는 변경하지 않습니다.

## 미리보기

저장소 루트에서 아래 명령을 실행한 뒤 `http://localhost:4173/`를 엽니다.

```sh
python3 scripts/build-guide.py
python3 scripts/verify-guide.py
python3 -m http.server 4173 --directory docs --bind 127.0.0.1
```

Node.js나 외부 패키지가 필요하지 않습니다. 자바스크립트를 꺼도 모든 가이드 내용을 읽을 수 있습니다. 검색, 분류와 고유 링크 이동은 자바스크립트로 동작합니다. 공통 메뉴의 ‘통합 검색’ 또는 `/` 키로 Q&A·전체 규칙·아이템·업그레이드 확률·캐릭터를 함께 검색합니다. 결과는 해당 설명의 고유 링크로 이동합니다. 방 변경사항은 통합 검색에서 제외하고 방 페이지의 층별 자체 검색을 유지합니다. Q&A와 캐릭터의 세부 설명은 지원 브라우저에서 CSS로 240ms 동안 펼치고 접습니다. 동작 줄이기 설정을 사용하거나 필요한 CSS 기능을 지원하지 않는 경우에는 기본 펼치기 동작을 사용합니다.

아이템 목록은 카드 높이에 맞춰 가장 짧은 열부터 채우는 Pinterest식 배치를 사용합니다. 세부 조건은 모달로 표시하여 카드 높이가 바뀌지 않게 합니다. 모달은 닫기 버튼·Esc·바깥 영역 클릭으로 닫고, 열었던 버튼으로 초점을 돌려줍니다. 창 크기 조절 중에는 재배치를 보류하고 조절이 끝난 뒤 한 번 정렬하며, 화면 근처 카드의 위치 변경만 애니메이션으로 표시합니다. 동작 줄이기 설정에서는 애니메이션을 생략합니다. 캐릭터 목록은 기존 그리드를 사용합니다. 자바스크립트나 모달을 지원하지 않는 환경에서는 기존 접기·펼치기를 사용하며, 인쇄에서는 전체 조건을 일반 흐름으로 표시합니다.

사이트는 입문 Q&A(`index.html`), 전체 규칙(`rules.html`), 아이템 가이드(`items.html`), 캐릭터 가이드(`players.html`), 업그레이드 확률(`upgrades.html`), 방 배치 변경사항(`rooms.html`)의 여섯 페이지로 구성합니다. 사이드바는 페이지 이동 메뉴이며, 챕터 목차는 해당 페이지 본문에 표시합니다. 작은 화면에서는 같은 페이지 메뉴를 상단에 표시합니다. 페이지 소개의 장식 이미지와 요약 카드는 사용하지 않습니다. 개별 아이템·캐릭터의 원본 이미지는 유지합니다. Q&A의 관련 링크는 세부 규칙·아이템·캐릭터 설명으로 바로 연결됩니다. 기존 아이템 설명의 고유 링크도 아이템 가이드로 이동합니다.

현재 화면은 입문 Q&A 25개, 아이템·장신구·카드 825종, 캐릭터 46종, 정식 방 파일 52개를 설명합니다. 아이템에는 기존 변경 561종과 Astro-Items 등록 264종이 포함됩니다. 이전에 설명한 모드 아이템 16종은 같은 카드에 효과를 병합하고 248종을 추가했습니다. 아이템은 출처(기존 아이템 변경·Astro-Items 추가), 종류(패시브·액티브·장신구·카드), 효과와 가격·퀄리티·충전으로 필터링합니다. 각 조건을 함께 적용하며 출처·종류 버튼의 개수는 나머지 선택 조건에 맞춰 갱신합니다. 배열의 등장 가중치·감소량·제외 기준 표와 업그레이드 설명이 없는 배열 전용 항목은 화면과 통합 검색에서 제외합니다. 아이템 효과 자체의 배열 사용 조건은 유지합니다. 방 페이지는 변경·추가·제거 프리셋의 원본과 대결 구성을 비교하며, 선택한 층의 자료만 불러옵니다. 같은 좌표에 여러 개체가 지정된 경우 동시에 생성되는 개체가 아니라 스폰 후보로 표시합니다. 임시 방 파일은 제외합니다.

## 설명의 기준 커밋 (내부 기록)

설명은 다음 커밋을 기준으로 검토했습니다. 확인 날짜는 2026-10-03이며 Astrobirth 버전은 1.385입니다.

| 저장소 | 기준 커밋 SHA |
| --- | --- |
| Astrobirth | `4c02a2072ac3a304072a5c7424efe06792f700d4` |
| Astro-Items | `b9785699358291b35eb4195dc5fcd8441ca39c52` |

기준값은 `docs/guide-content.json`의 `sources`에서 관리합니다. 생성기는 이 값과 확인 날짜·버전을 모든 페이지의 `Guide maintenance baseline` HTML 주석에 기록합니다. 사이트 화면에는 표시하지 않습니다. 기준 커밋은 게임 기능을 검토한 범위이며, 문서의 `gh-pages` 커밋이나 배포 시점과 별개입니다. 문구·레이아웃 수정이나 HTML 재생성만으로 기준값을 변경하지 않습니다.

다음 정보 갱신에서는 저장소마다 새 검토 대상 커밋을 정하고, 기록된 SHA부터 그 커밋까지의 변경 이력과 차이를 확인합니다. 변경된 기능의 설명·근거·검토 목록을 갱신하고 검증을 마친 뒤 `sources`, 버전과 확인 날짜를 함께 갱신합니다. `scripts/guide-coverage.json`의 기준 커밋도 일치시킵니다. 일부만 확인했다면 전체 기준 커밋을 앞당기지 말고 아직 검토하지 않은 변경사항을 내부 기록에 남깁니다. 미커밋 게임 변경사항은 기준 범위에 포함하지 않습니다.

## 내용 수정

1. Q&A는 `guide-content.json`, 전체 규칙은 `rules-content.json`, 아이템은 `items-content.json`, 플레이어는 `players-content.json`에서 설명과 근거 파일 경로를 수정합니다. 방 요약은 `rooms-content.json`, 프리셋 자료는 `assets/rooms/*.json`에서 관리합니다.
2. 실제 변경을 확인한 커밋 SHA, 버전과 확인 날짜를 함께 갱신합니다. Astrobirth와 Astro-Items의 근거를 따로 관리합니다.
3. `python3 scripts/build-guide.py`로 HTML을 갱신하고 `python3 scripts/verify-guide.py`로 항목 수, 고유 링크, 이미지, 표와 근거 자료의 대응을 확인합니다. 공통 화면은 `scripts/guide-layout.html`에서 관리합니다.
4. 작은 화면과 넓은 화면에서 페이지·목차 이동, 검색·분류, 펼치기, 이미지와 고유 링크를 확인합니다.

`search-index.json`은 생성기가 다섯 페이지의 설명 원본에서 함께 생성합니다. 표와 세부 조건, 영문 이름과 기존 검색어, 추가 아이템의 전체 EID 효과와 효과에 언급된 아이템 이름을 포함하며 코드 근거·HTML 주석·에이전트 메모는 제외합니다. 검색창을 처음 사용할 때 필요한 자료를 불러옵니다. 아이템·캐릭터의 분류 버튼은 각 페이지에서 유지하며, 검색 결과로 들어간 설명은 분류 조건과 관계없이 열립니다. 설명을 갱신할 때 검색 자료를 별도로 작성하지 말고 HTML과 함께 재생성합니다.

업그레이드 확률은 `upgrades-content.json`의 `patterns`에서 관리합니다. 자동 대체 49종(일반 38종·행성 11종)과 자동 확률 0%인 직접 변환 전용 13종을 원본·강화 아이템·확률·조건으로 보존합니다. `scripts/guide_upgrades.py`가 이 자료를 아이템 카드의 강화 관계와 통합 검색에 함께 반영하므로 아이템 설명을 다시 가져와도 업그레이드 설명은 유지됩니다. 제작 조합은 같은 파일의 `directPatterns`에서 관리하며 입문 Q&A의 조건과 함께 검토합니다. 기준 커밋 전체를 바꾸지 않고 해당 확률 표의 검토 날짜와 원본 해시를 따로 기록합니다.

기준 커밋의 업그레이드 표를 다시 가져올 때에는 다음 명령을 실행한 뒤 직접 변환 조건과 기존 문구를 검토합니다. EID 이름 표만 필요하며 게임 콜백을 실행하지 않습니다.

```sh
python3 scripts/import-guide-upgrades.py --base-mod ../Astro-Items --eid '../external item descriptions_836319872'
python3 scripts/build-guide.py
python3 scripts/verify-guide.py
```

입문 Q&A의 아이템 업그레이드 챕터는 자동 변환 확률, 초행성·별자리 조건, 버리기 버튼 조합과 아이템별 직접 변환을 설명합니다. 원본 아이템이 새로 결정될 때의 확률 판정과 현재 방 바닥 아이템을 직접 바꾸는 조건을 구분하며, 소지 재료의 소모 여부와 관련 아이템 효과 링크를 함께 기록합니다.

입문 Q&A의 첫 챕터는 노피격·올백(방송 명칭 에이플)입니다. 전체 기능과 구간별 추가 보상, 올백과 무관한 공통 보상을 별도로 설명합니다. `effectGroups`는 기능별 목록, `rewardTable`은 조건·보상 표입니다. 아이템 카드의 `detailsFrom`은 같은 ID의 Q&A 상세 내용을 공유하여 조건이 어긋나지 않게 합니다.

아이템 카드의 `kind`는 분류 버튼에 대응하며 `origin`은 기존 아이템 변경(`base`)과 Astro-Items 추가(`mod`)를 구분합니다. 플레이어는 `origin`(기본 `base`·모드 `mod`)과 `variant`(일반 `normal`·더럽혀진 `tainted`)를 각각 필터링하며 두 조건을 함께 적용합니다. 각 필터의 인원수는 다른 필터에서 선택한 조건에 맞춰 갱신합니다. 캐릭터 카드에도 구분과 형태를 함께 표시합니다. 플레이어의 기존 `kind`는 원본 설정과 이미지 출처를 연결하는 내부 분류로 유지합니다. `image`는 `docs` 기준 상대 경로이며, `relatedLinks`에 다른 페이지의 카드나 Q&A 링크를 추가할 수 있습니다. HTML과 이미지 경로는 생성 과정에서 중복 ID·이미지 존재 여부를 검사합니다.

추가 아이템의 한국어 이름과 효과는 Astro-Items의 EID 등록값을 사용합니다. `eidEffects`는 효과별 줄의 목록이며 각 줄은 `text`(문자열), `item`(EID 아이템 이름), `icon`(EID 아이콘 키) 조각으로 구성합니다. 생성기는 문자 조각을 HTML로 해석하지 않고 그대로 표시하며, 아이템 조각에는 이름과 아이콘을 함께 표시합니다. 카드 본문에는 EID의 기본 효과를 모두 표시합니다. 추가 아이템은 핵심 효과부터 설명합니다. 연출 방식이나 대결 전용 예외를 대표 설명에 앞세우지 않고 세부 조건으로 분리합니다. ‘세부 조건 보기’에는 중첩 효과·캐릭터 예외·대결 규칙 등 실제 추가 조건만 넣으며 기본 효과를 반복하지 않습니다. 통합 검색 결과의 요약에는 첫 3줄을 사용하되 전체 효과를 검색 대상으로 유지합니다. 시간 충전은 초 단위로, 스테이지 진입·적 피해·피격 횟수로 관리되는 충전은 해당 조건으로 표시합니다. 일반 0충전은 ‘충전 불필요’입니다. 원본 `maxcharges`와 `chargetype`은 내부 자료에 보존하며 검토한 `chargeLabel`을 화면에 사용합니다. 전체 효과는 통합 검색에 포함합니다. 이미 설명이 있는 모드 아이템은 기존 카드와 고유 링크를 유지하여 EID 효과를 병합하며, 대결 중 변경되는 규칙·조건·보상 설명은 별도로 유지합니다.

설명은 EID를 바탕으로 하되 오타·잘못된 조사·중복 명칭은 자연스럽게 다듬습니다. 원문은 `astro-items.json`의 `eidDescription`에 보존하고, 문장 수정은 `astro-item-review.json`의 `corrections`에 전후 문구와 검토 이유를 기록합니다. 가져오기 도구가 이 보정을 적용하므로 자료를 다시 가져와도 수정이 유지됩니다. 내부 처리 표현은 사용자가 보게 되는 결과로 설명하며, 추가 조건에서는 본문에 이미 있는 기본 효과를 반복하지 않습니다. 연속된 아이템 참조 목록의 쉼표는 `guide_presentation.py`에서 표시할 때만 추가하며 원본 이름·순서는 유지합니다.

`astro-items.json`은 Astro-Items 기준 커밋의 `content/items.xml` 등록 264종, 한국어 EID 원문·정규화 효과, 이미지와 구현 파일의 해시를 보존합니다. 추가 효과는 2026-10-04에 검토했습니다. `astro-item-review.json`에는 EID와 실제 구현이 다른 부분의 보정, 캐릭터별 예외와 충전 방식, 근거를 기록합니다. 프로메테우스의 저주 예외와 엄청 쉬움 모드의 실제 체력 제한은 기존 대결 설명과 일치시킵니다. 미작성 EID를 가진 마법의 소라고동은 효과 설명 미등록으로 표시합니다. 등록 이미지가 없는 Blue Stew·Green Stew·Brown Stew·Marker Pocket·Witchcraft·Artifact Ignition 6종은 게임 원본 물음표 이미지를 사용하며 `imagePlaceholder`에 기록합니다. 삼체도 다른 아이템과 동일하게 EID 효과·중첩 설명을 표시합니다.

추가 아이템 자료를 다시 가져올 때에는 Lupa가 있는 Python 환경과 기본 게임 리소스, 설치된 EID를 사용합니다. 가져오기 도구는 `guide-content.json`의 Astro-Items 기준 커밋을 읽습니다. 게임 이벤트는 실행하지 않고 EID 설명을 등록하는 초기화만 평가합니다. 커밋을 바꿀 때에는 기존 설명 보정과 추가 조건을 먼저 다시 검토해야 합니다. 배포 빌드는 저장된 자료만 사용하므로 Lupa나 설치된 게임은 필요하지 않습니다.

```sh
python3 scripts/import-guide-astro-items.py --baseline ../../extracted_resources/resources --eid '../external item descriptions_836319872' --base-mod ../Astro-Items
python3 scripts/audit-guide-coverage.py --baseline ../../extracted_resources/resources --base-mod ../Astro-Items
python3 scripts/build-guide.py
python3 scripts/verify-guide.py
```

`resource-changes.json`에는 기본 게임과 다른 아이템 속성·퀄리티·분류·배열 값을, `entity-changes.json`에는 적의 속성·하위 정의·추가 등록과 외형 자료의 차이를 보존합니다. 같은 배열 이름이 중복 정의된 경우 두 값을 모두 보존합니다. `items-content.json`에는 기존 741개 원본 항목과 추가한 248개 항목, `poolTable`을 함께 보존하며, 생성기가 배열 표를 제외합니다. 배열만 변경된 원본 171개 중 업그레이드 관계가 있는 7개는 효과 설명을 추가해 표시하고, 나머지 164개는 제외합니다. 검토 목록의 아이템 개수와 배열만 변경된 항목의 연결은 화면 개수가 아닌 원본 자료를 기준으로 확인합니다. 아이템 정의가 없는 번호는 허구의 아이템 카드를 만들지 않고 전체 규칙에서 따로 설명합니다. 자료에는 확인한 원본 파일 해시를 포함합니다.

`scripts/guide_presentation.py`는 검토한 원본 문장을 보존하면서 카탈로그 화면의 반복 문구를 정리합니다. 퀄리티·조합 퀄리티·가격·충전·분류 변경은 카드의 변경 값 행으로, 플레이어의 시작방 추가 보상과 단순 시작 체력·소모품 설정은 아이콘과 수치로 표시합니다. 고유 효과·추가 지급·임시 체력·멀티플레이 조건처럼 단순한 설정 값으로 바꿀 수 없는 설명은 그대로 유지합니다. 설정만 바뀐 아이템의 일반 안내 문장과 캐릭터별 ‘추가 금지 없음’ 문장은 생략합니다. 황금·강화 장신구 조건은 해당 카드에 짧게 표시하고, 퀄리티 판정·가격 보정·시작방과 소지 아이템의 구분·금지 범위는 각 카탈로그의 `sharedNotes`에서 한 번 설명합니다. 공통 설명도 통합 검색에 포함합니다.

`guide-icons.json`은 이름별 원본 이미지와 EID 아이콘 프레임을 연결합니다. EID의 퀄리티·체력·소모품·카드 아이콘은 원본 PNG를 SVG에 포함하고 ANM2 프레임의 영역만 표시합니다. 시작방 보상과 캐릭터별 금지 목록에는 아이콘과 EID 이름을 함께 표시합니다. 아이콘은 이름·수치의 보조 자료이며 텍스트는 유지합니다. SVG는 외부 파일을 불러오지 않으므로 GitHub Pages에서도 동일하게 표시됩니다. 원본 이미지 해시·프레임·자르기 영역과 이름 표 해시를 내부 자료에 기록합니다.

아이콘 자료를 갱신할 때에는 다음 명령을 사용합니다. 설치된 EID와 대응하는 원본 리소스가 있어야 하며, 배포 빌드에는 이 도구나 설치된 모드가 필요하지 않습니다.

```sh
python3 scripts/import-guide-icons.py --baseline ../../extracted_resources/resources --eid '../external item descriptions_836319872' --base-mod ../Astro-Items
```

추출된 기본 게임 리소스와 설치된 EID 이름 표가 있는 환경에서는 다음 명령으로 아이템 설정을 갱신할 수 있습니다. 기본 게임의 버전을 바꾸면 기존 비교 자료를 그대로 재사용하지 말고 각 차이를 다시 검토해야 합니다.

```sh
python3 scripts/import-guide-resources.py --baseline ../../extracted_resources/resources --eid '../external item descriptions_836319872'
python3 scripts/audit-guide-coverage.py --baseline ../../extracted_resources/resources --base-mod ../Astro-Items
python3 scripts/build-guide.py
python3 scripts/verify-guide.py
```

`scripts/guide-coverage.json`은 확인한 커밋의 활성 Lua 58개와 Astro-Items의 대결 분기 22개를 해당 설명에 연결하며, 기능별 검토 항목과 나머지 XML 차이를 기록합니다. 감사 갱신 도구는 저장된 기능별 검토 목록을 유지합니다. 새 검토 자료는 `--feature-review`로 지정할 수 있습니다. 출처 연결이 있다는 사실만으로 설명의 정확성을 보장하지 않습니다. 조건과 수치, EID 이름을 실제 코드와 대조한 뒤 검증해야 합니다. 미커밋 게임 디버깅 변경은 배포 설명의 기준에서 제외합니다.

테마는 Astrobirth 대표 썸네일의 남색·파랑을 기본으로 사용하며, 보라색을 보조 강조색으로 사용합니다.

고유 링크는 각 제목 옆의 링크 아이콘으로 표시합니다. 근거 코드 링크는 화면에 표시하지 않고, 해당 설명의 HTML 주석 `Agent reference material`에 항목 ID·저장소·커밋·파일 경로·URL과 외부 참고 자료(`references`)를 JSON으로 보존합니다. 이후 내용 검토 시 JSON 원본 또는 생성된 HTML 주석을 참고할 수 있습니다. 사람을 위한 관련 Q&A·아이템·캐릭터 링크는 그대로 표시합니다.

기존 Q&A 제목은 최초 작성 문구를 사용하며, 질문형과 ‘사라졌어요’ 같은 상황 설명형을 함께 허용합니다. 일시정지 표현과 EID 명칭 등 별도로 확정한 수정은 유지합니다. 이후 추가한 Q&A는 해당 항목의 최초 문구를 유지합니다. 그 외 제목은 간결한 명사형을 사용하며, 설명문은 ‘입니다·합니다’체로 통일합니다. 설명에는 확인한 기능만 적습니다. 방송별 목표나 밴 해제 허용 같은 운영 규칙은 별도로 확인해야 합니다. ‘엄청 쉬움 모드’의 체력 상한은 EID 문구와 현재 실행 코드가 다르므로, 실행 코드를 근거로 설명합니다.

`assets/items`는 게임 원본 아이템·장신구 아이콘이며, `assets/players/*-emotion.png`는 게임과 Astro-Items의 캐릭터 skin에서 이모션 프레임을 잘라 사용합니다. 일반·더럽혀진 캐릭터 34종과 모드 캐릭터 12종 모두 맨 왼쪽 가운데 칸(`x=0, y=192, 64×64`)을 사용합니다. 해당 칸은 공통 플레이어 애니메이션의 `Pickup` 첫 프레임에도 지정되어 있습니다. 머리·몸통·머리카락을 따로 합성하지 않으며, 원본 픽셀의 색·크기를 변경하지 않고 투명 여백만 제거한 뒤 2픽셀 여백을 둡니다. 에덴과 더럽혀진 에덴은 게임 원본에서 같은 skin을 사용하므로 이모션 그림도 동일합니다. 아이템의 한글·영문 이름은 설치된 External Item Descriptions의 이름 표를 기준으로 했습니다. 모드 아이템·캐릭터의 한국어 이름은 Astro-Items의 EID 등록값을 사용하며, 방송 별칭은 검색어로 유지합니다. 게임 이미지의 권리는 원 제작자에게 있으며, 모드 이미지는 TeamHY/Astro-Items의 원본입니다.

`player-sprites.json`에는 출력 이미지·픽셀 해시, 원본 skin·캐릭터 설정·공통 애니메이션의 출처 해시와 기준 커밋, 프레임 좌표·투명 여백 제거 영역을 보존합니다. 가이드 검증기는 46종의 이미지 연결, 자르기 기준·출력 크기, 모드 캐릭터 이미지 중복과 출처 커밋의 파일 해시를 확인합니다. 이미지를 갱신하려면 Pillow가 있는 Python 환경에서 다음 명령을 실행하고 가이드를 재생성합니다. 배포 빌드에서는 저장된 PNG만 사용하므로 Pillow가 필요하지 않습니다.

```sh
python3 scripts/import-guide-player-sprites.py --baseline ../../extracted_resources/resources --base-mod ../Astro-Items
python3 scripts/build-guide.py
python3 scripts/verify-guide.py
```

## GitHub Pages

- 게임 코드의 `main` 브랜치와 문서 배포를 분리합니다. 문서 커밋에는 `docs/**`, 가이드 생성기·공통 템플릿과 배포 작업만 포함합니다.
- 배포 대상: `TeamHY/Astrobirth`의 `docs` 폴더만 업로드합니다.
- 배포 주소: `https://teamhy.github.io/Astrobirth/`
- 저장소의 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 설정합니다.
- 문서 전용 `gh-pages` 브랜치에 가이드 파일이 변경되면 `Publish viewer guide` 작업이 생성·배포합니다. 수동 실행도 가능합니다.
- 스타일, 스크립트, 이미지에 상대 경로를 사용하여 저장소 하위 경로에서도 동작합니다.
- 빌드 도구나 서버 실행 없이 `index.html`을 직접 열어 읽을 수도 있습니다.

작업 구성은 [GitHub Pages 공식 문서](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)를 기준으로 합니다.
